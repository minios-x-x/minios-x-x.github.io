소개

4년 9개월 차 iOS 개발자입니다. 헬스케어 서비스의 환자용·약사용 앱 두 개를 iOS 1인 개발자로 전담하며, Storyboard 기반 앱을 새 디자인과 함께 코드 기반 MVVM 구조로 처음부터 다시 만들었고, 이후 SwiftUI 전환과 async/await 전환을 주도했습니다.

처음 다루는 문제는 레퍼런스와 오픈소스 코드를 직접 조사해 풀어가는 편입니다. 첫 회사에서 채팅 UI를 조사하며 직접 구현한 경험이 다음 회사에서 Sendbird UIKit 대신 채팅 화면을 자체 구현하는 결정으로 이어졌고, 약국 통계 화면에서는 차트 라이브러리 없이 SwiftUI로 차트를 직접 그렸습니다.

최근에는 TCA(The Composable Architecture)를 개인 프로젝트로 학습하며 과정을 블로그에 기록하고 있고, Claude Code 같은 AI 코딩 도구를 실제 구현에 적극적으로 활용하고 있습니다.

  • Sendbird UIKit 대신 SendbirdChat SDK 위에 UICollectionView로 채팅 화면을 직접 구현해, 업무에 맞는 UI를 자유롭게 바꿀 수 있는 구조 확보
  • 페이징, 읽음 표시, 키보드 높이 대응, 캐시된 메시지를 먼저 보여준 뒤 서버 메시지로 갱신하는 로딩 방식 구현
  • 여러 장 이미지 전송, 파일 뷰어, 메시지 삭제, 자주 쓰는 문구, 차단·알림 끄기, 온라인 상태 표시 구현

  • 프로토콜 기반 Worker로 의존성을 주입하도록 바꿔, Mock 객체로 단위 테스트를 할 수 있는 구조 확보
  • 로그인·Splash·홈·약국 등록·채팅·결제까지 화면 단위로 순서를 정해 RxSwift·콜백 코드를 async/await로 전환하고 레거시 코드 제거

카카오·애플 소셜 로그인, 일반 로그인, 본인인증, 탈퇴 처리 코드가 여러 화면에 흩어져 있어 하나로 모으기로 결정.

  • 로그인 관련 로직을 LoginService 모듈로 분리하고 소셜 로그인과 일반 로그인 흐름을 나눔
  • 토큰 재발급, PASS 본인인증, 탈퇴 요청 계정 처리 등 예외 상황을 모듈 안에서 일관되게 처리

결제·처방전 데이터 암호화

카드 정보와 처방전 이미지 같은 민감 데이터를 안전하게 전송해야 해서 표준 암호화 방식을 적용.

  • 카드 정보는 RSA, 처방전 이미지는 AES-GCM으로 암호화하는 로직을 Cryptable 프로토콜로 추상화해 앱 전반에서 같은 방식으로 사용하도록 모듈화
  • 이미지 암호화는 처음 다루는 영역이라 직접 조사해 AES-GCM 방식을 선정
