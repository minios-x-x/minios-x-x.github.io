소개

4년 9개월 차 iOS 개발자입니다. 헬스케어 서비스의 환자용·약사용 앱 두 개를 iOS 1인 개발자로 전담하며, Storyboard 기반 앱을 새 디자인과 함께 코드 기반 MVVM 구조로 처음부터 다시 만들었고, 이후 SwiftUI 전환을 주도했습니다.

처음 다루는 문제는 레퍼런스와 오픈소스 코드를 직접 조사해 풀어가는 편입니다. 첫 회사에서 채팅 UI를 조사하며 직접 구현한 경험이 다음 회사에서 Sendbird UIKit을 걷어내고 채팅 화면을 자체 구현하는 결정으로 이어졌습니다.

최근에는 TCA(The Composable Architecture)를 개인 프로젝트로 학습하며 과정을 블로그에 기록하고 있고, Claude Code 같은 AI 코딩 도구를 실제 구현에 적극적으로 활용하고 있습니다.

SwiftUI 단계적 전환

Apple의 SwiftUI 중심 흐름에 대비해 지금부터 전환 경험을 쌓아야 한다고 판단해 자발적으로 진행.

  • 신규 화면은 SwiftUI로 개발하고, 기존 화면은 영향도가 낮은 순서로 바꾸는 우선순위 전략 수립
  • UIHostingController 기반 BaseView·BaseViewController로 UIKit과 SwiftUI가 공존하는 하이브리드 구조 설계
  • 전체 화면의 82%(모바일약국), 58%(약사님용)를 SwiftUI로 전환

채팅 화면 자체 구현

Sendbird UIKit의 기본 화면으로는 약사 업무에 맞는 UI를 만들기 어려웠고, 이전 회사에서 채팅 UI를 직접 구현해 본 경험이 있어 자체 구현으로 결정.

  • Sendbird UIKit 기반 채팅 화면을 걷어내고 UICollectionView로 다시 구현해, 업무에 맞는 UI를 자유롭게 바꿀 수 있는 구조 확보

네트워크 계층 개선

비즈니스 로직이 네트워크 코드에 직접 의존하면 테스트가 어렵다고 판단해 구조를 바꿈.

  • 프로토콜 기반 Worker로 의존성을 주입하도록 바꿔, Mock 객체로 단위 테스트를 할 수 있는 구조 확보
  • RxSwift(Input/Output) 기반 네트워크 코드를 Swift Concurrency(async/await)로 다시 작성해 비동기 흐름의 가독성 개선

결제·처방전 데이터 암호화

카드 정보와 처방전 이미지 같은 민감 데이터를 안전하게 전송해야 해서 표준 암호화 방식을 적용.

  • 카드 정보는 RSA, 처방전 이미지는 AES-GCM으로 암호화하는 로직을 Cryptable 프로토콜로 추상화해 앱 전반에서 같은 방식으로 사용하도록 모듈화
  • 이미지 암호화는 처음 다루는 영역이라 직접 조사해 AES-GCM 방식을 선정

재사용 UI 컴포넌트

반복되는 UI를 화면마다 새로 만들면 공수가 계속 늘어난다고 판단해 공통 컴포넌트로 정리.

  • 디자인팀이 Figma에 정의한 규격을 그대로 옮긴 EmptyStateView 등 공통 컴포넌트를 만들어, 화면마다 따로 구현하던 작업을 없앰
  • 이전 프로젝트에서 쓰던 오픈소스 SegementSlide를 private fork로 관리하며 사내 공용 모듈로 발전시키도록 설계
